## 1. 오늘 활동

운영 환경을 기준으로 성능과 안정성을 전반적으로 보완했다. EC2 CPU·메모리·디스크와 서비스 상태를 한 화면에서 볼 수 있도록 모니터링을 확장했고, Spark의 중복 Action을 줄였다. 또한 Comfort Score와 Confidence가 실제 데이터 분포를 더 잘 반영하도록 기준을 조정하고, 불필요하게 실행되던 Serving API CD 조건도 정리했다.

## 2. Keep

* **가정이 아니라 실제 데이터를 보고 기준을 수정한 것.** Confidence가 대부분 0이 되는 현상을 확인한 뒤 일정 통행량 이하를 모두 버리는 방식 대신 적은 관측도 일부 evidence로 인정하도록 변경했다.

* **운영 상태를 서비스 하나가 아닌 시스템 전체 관점에서 본 것.** 각 EC2와 Kafka, Airflow, Spark Streaming 등의 상태를 한 화면에서 확인할 수 있도록 구성했다.

  * Action: 모니터링을 설계할 때 개별 Metric보다 **현재 파이프라인이 정상적으로 동작하는지를 빠르게 판단할 수 있는 구조**를 만든다.

## 3. Problem

* **코드 자체는 정상이더라도 운영 환경에서는 예상하지 못한 낭비와 오탐이 있었다.** Metric이 없는 상태를 장애로 판단하거나, 다른 서비스의 dependency 변경 때문에 Serving API 배포까지 실행되는 경우가 있었다.

  * 개선 Action: 설정과 배포 조건도 코드처럼 **실제 의존성과 운영 상황을 기준으로 검증**한다.

## 4. Try

* 성능·점수·알람의 임계값을 정할 때 실제 운영 데이터를 일정 기간 수집한 뒤 기준을 지속적으로 보정해 본다.
