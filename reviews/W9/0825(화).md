## 1. 오늘 활동

Transform 2의 Spark 연산을 집중적으로 최적화했다. 반복되던 aggregation과 Window 연산을 줄이고, Map Matching을 `mapInPandas` 내부에서 후보 탐색부터 최종 선택까지 처리하도록 변경했다. 또한 Grafana Alert를 받아 장애를 확인하고 제한된 범위에서 자동 조치하는 Ops Agent의 기본 구조를 구현했다.

## 2. Keep

* **결과는 유지하면서 비효율적인 연산 구조만 줄인 것.** Map Matching과 Feature 계산 결과가 기존과 동일한지 regression test를 유지하면서 중복 Window, count, aggregation을 줄였다.

* **자동 복구 범위를 제한한 것.** 모든 장애를 자동으로 처리하지 않고 Stream Processor 재시작처럼 위험도가 낮은 조치만 허용하고, Kafka·EMR·DB 등은 알림 중심으로 남겼다.


## 3. Problem

* **오래된 브랜치에서 작업하면서 이미 반영된 Map Matching 코드가 다시 이전 구조로 돌아가는 문제가 발생했다.**
