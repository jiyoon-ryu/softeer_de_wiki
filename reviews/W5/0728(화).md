## 1. 오늘 활동
- **한 일**: 최종 프로젝트 주제 선정을 위해 **NYC TLC 택시 데이터를 활용한 Data Product 아이디어를 브레인스토밍하고 구체화**함.
  - 단순 분석에서 끝나는 주제보다 **사용자가 반복적으로 사용하고 실제 의사결정으로 이어지는 서비스**를 목표로 방향을 탐색함.
  - Spark/Airflow 및 스트리밍 환경을 자연스럽게 활용할 수 있는지 함께 검토함.
  - 자율주행 택시 도입, 기사 수익 최적화, 택시 인캐빈 맞춤 광고를 주요 후보로 좁혔으며, 관광·부동산·WAV·DRT 등 다양한 도메인과의 결합 가능성도 검토함.

## 2. Keep
- **TLC가 반드시 메인 데이터가 되어야 한다는 기준을 유지한 것.**
  - IMU, 사고, 날씨, 관광, 부동산 등의 외부 데이터를 활용하더라도 서비스의 핵심이 외부 데이터로 넘어가지 않도록 확인함.
  - TLC는 이동 수요, OD, 대기시간, 이동시간 등 핵심 가치를 제공하고 외부 데이터는 맥락을 보강하는 역할로 정리함.
  - Action: 앞으로도 주제를 평가할 때 **"TLC가 빠져도 이 서비스가 성립하는가?"를 먼저 확인**하고, 성립한다면 TLC 활용도가 약한 주제로 판단한다.

- **분석 결과가 아니라 실제 행동을 만드는 Data Product를 고민한 것.**
  - "어디서 사고가 많이 나는가", "어디서 택시 수요가 높은가"에서 끝내지 않고,
    - 자율주행차를 어디부터 도입할지
    - 기사가 어디로 이동할지
    - 어떤 광고를 노출할지
    와 같이 결과가 구체적인 의사결정으로 이어지도록 발전시켰다.
  - Action: 주제 정의 시 항상 **사용자 → 문제 → 데이터 → 추천/행동** 순서로 설명해본다.

- **Spark/Airflow를 억지로 넣지 않고 서비스 구조와 연결하려고 한 것.**
  - TLC를 스트리밍 데이터라고 가정하고 실시간 이동 데이터 처리, 과거 대규모 데이터 집계, 외부 Context 갱신을 나누어 생각함.
  - Spark는 대량 데이터 처리, Airflow는 반복 파이프라인 운영이라는 역할을 정리함.
  - Action: 최종 주제 선정 시 **각 기술이 없으면 어떤 문제가 생기는지 설명할 수 있는 주제**를 선택한다.

## 3. Problem
- **아이디어 범위를 너무 넓게 탐색하면서 주제 방향이 자주 바뀌었다.**
  - 관광, 부동산, 사고, IMU, WAV, 셔클 등 다양한 방향을 검토하면서 새로운 아이디어는 많이 얻었지만, 실제 구현 가능성과 프로젝트 범위를 동시에 비교하기 어려워졌다.
  - 개선 Action: 이제는 새로운 주제를 계속 추가하기보다 **최종 후보 3개를 동일한 기준으로 비교해 하나를 선택**한다.

- **실제 TLC에 존재하지 않는 데이터를 자연스럽게 사용할 뻔한 경우가 있었다.**
  - 승객 나이·관심사 기반 Passenger Persona
  - 운행 중 실시간 GPS 위치
  - 실제 기사 근무시간 및 공차시간
  등은 공개 TLC 데이터만으로 알 수 없다.
  - 개선 Action: 기능을 정의할 때 **실제 제공 컬럼 / 파생 가능한 값 / 외부 데이터 / 시뮬레이션 데이터**를 명확하게 구분한다.

- **자율주행 도입 추천은 아이디어는 강하지만 반복 서비스성이 약할 수 있다.**
  - "어디부터 도입할 것인가"는 자주 발생하는 의사결정이 아니기 때문에 Airflow나 스트리밍 활용이 약해질 수 있다.
  - 개선 Action: 자율주행 주제를 선택할 경우 **초기 Rollout Planner + 도입 후 일일 운행 적합도 Monitor**로 확장해 지속적으로 활용되는 서비스로 만든다.

- **맞춤 광고의 효과를 검증하려면 추가 데이터가 필요하다.**
  - TLC에는 광고 노출, 클릭, 구매 데이터가 없기 때문에 추천만 하고 끝나면 실제 광고 효과를 평가할 수 없다.
  - 개선 Action: 광고 주제를 선택하면 `impression → click → conversion` 형태의 **광고 Interaction Stream을 별도로 설계하고, A/B Test 및 CTR·Conversion Lift로 효과를 평가**한다.

## 4. Try 
- **최종 후보 3개 중 주제를 확정**

  1. **Autonomous Taxi Rollout Planner**
     - TLC 이동 수요 + 사고 + 도로환경을 활용해 AV의 초기 도입 지역·시간·조건 및 단계적 확장 순서 추천

  2. **Driver Opportunity Navigator**
     - 현재 위치와 이동 수요를 기반으로 기사의 다음 영업지역 및 기대 운행수익 추천

  3. **Trip Context Ads**
     - 출발지·목적지·시간 등의 Trip Context를 기반으로 택시 뒷좌석 광고를 실시간 추천하고 광고 반응을 다시 학습

- **가정과 실제 데이터를 명확하게 분리한다.**
  - TLC 원본은 실제 데이터를 사용한다.
  - 실시간 시스템 구현이 필요하면 **historical TLC 데이터를 시간순으로 replay해 Trip Stream을 생성**한다.
  - 실제로 존재하지 않는 GPS, 광고 반응 등의 데이터는 시뮬레이션 데이터임을 명시한다.

- **주제 선정 기준을 체크리스트화한다.**
  - TLC 중심성
  - 사용자 문제 명확성
  - 반복 사용성
  - Spark 필요성
  - Airflow 필요성
  - 외부 데이터 확보 가능성
  - 구현 난이도
  - 발표 임팩트

  위 기준으로 세 후보를 평가한 뒤 최종 주제를 결정한다.
