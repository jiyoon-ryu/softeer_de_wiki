## 1. 오늘 활동

* **한 일:** 팀 프로젝트 **“Road Comfort API”**의 데이터 처리 흐름과 AWS 아키텍처를 구체화했다.
* 센서 데이터를 `Bronze → Silver → Gold` 단계로 처리해 **LION 도로 세그먼트별 Comfort Score**를 생성하는 구조를 정리했다.
* API는 경로를 직접 추천하는 것이 아니라, **경로 추천 알고리즘이 활용할 수 있는 세그먼트별 승차감 데이터**를 제공하는 역할로 범위를 좁혔다.

## 2. Keep

* **API의 역할과 프로젝트 범위를 명확히 한 것.**
  경로 추천 자체와 Comfort Score 제공 기능을 분리하면서 구현 범위가 명확해졌다.

  * **Action:** 다음 프로젝트에서도 시스템이 직접 담당하는 범위를 먼저 정한다.

* **데이터 처리 과정을 단계별로 구체화한 것.**
  원천 센서 데이터가 어떤 과정을 거쳐 최종 Score가 되는지 명확히 정리했다.

  * **Action:** 파이프라인 설계 시 각 단계의 입력·처리·출력을 먼저 정의한다.

## 3. Problem

* **초기에는 데이터 수집, 처리, Score 계산의 역할이 섞여 있어 구조가 복잡했다.**
* 실제 프로젝트 규모보다 아키텍처를 크게 잡으면서 불필요한 구성까지 포함할 가능성이 있었다.

  * **개선 Action:** 필요한 기능과 기술만 남기고, 실제 구현 가능한 범위인지 먼저 검토한다.

  Jerk, 급가속·급제동, 도로 특성 등이 Score에 어떻게 반영되는지 확정한다.
