## 1. 오늘 활동

- **한 일:** 팀 프로젝트에서 **TLC Zone별 특성을 구축하기 위한 데이터 수집·가공 파이프라인**을 구현했다.
- TLC Zone Lookup과 Geometry를 결합하여 `location_id` 기준의 **`zone_master`**를 구축했다.
- PLUTO, ACS, LODES, OSM POI, MTA, NYC Facilities, Parks 데이터를 TLC Zone에 연결하여 **`zone_profile_features.parquet`**을 생성했다.

## 2. Keep

- **외부 데이터를 결합하기 전에 기준 테이블을 먼저 만든 것.** 모든 데이터를 `location_id` 기준으로 연결할 수 있도록 `zone_master`를 먼저 구축하면서 이후 처리 구조가 단순해졌다.
  - **Action:** 여러 데이터 소스를 결합할 때 공통 기준이 되는 Master 데이터를 먼저 정의한다.
- **원천 데이터를 바로 점수화하지 않고 Feature 단계로 분리한 것.** 토지 이용, 인구, 고용, POI 등 원천 특성을 Zone 단위로 먼저 집계했다.
  - **Action:** 원천 데이터 → Feature → 최종 지표의 단계를 분리하여 각 단계의 역할을 명확히 한다.

## 3. Problem

- **데이터마다 공간 단위와 형식이 달라 TLC Zone에 연결하는 방식이 복잡했다.**
- 면적·거리 계산과 저장에 사용하는 좌표계가 달라 동일한 CRS로 모든 연산을 처리할 수 없었다.
  - **개선 Action:** 저장 좌표계와 공간 연산용 좌표계를 구분하고, 데이터 소스별 전처리·Spatial Join 과정을 명확히 정의한다.

## 4. Try

- `zone_profile_features`를 활용해 **Zone의 지역적 특성을 정량화하는 기준**을 구체화한다.
- 각 Feature의 결측값과 이상값을 추가 검증한다.
- 구축한 Zone Feature가 실제 NYC 지역 특성을 적절히 반영하는지 대표 Zone을 기준으로 확인한다.
