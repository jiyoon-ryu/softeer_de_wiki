## 1. 오늘 활동

Open-Meteo를 이용해 Zone별 날씨를 수집하는 기능을 구현하고, 최신 날씨를 관리하는 저장 구조와 15분 주기의 Airflow DAG를 구성했다. Spark가 필요하지 않은 날씨 수집 작업은 별도의 Spark Job 대신 가벼운 Python Task로 실행하도록 변경했다.

## 2. Keep

* **작업의 특성에 맞게 실행 환경을 다시 선택한 것.** 처음 구조를 그대로 유지하기보다 단순 API 호출과 DB 적재에는 Spark가 필요하지 않다고 판단해 Airflow의 lightweight task로 분리했다.

  * Action: 기존 아키텍처에 맞추기보다 **작업량과 처리 특성에 맞는 가장 단순한 실행 방식을 먼저 고려**한다.

## 3. Problem

* **주기적으로 갱신되는 데이터에서는 단순 UPSERT만으로 충분하지 않았다.** 이전 실행이 늦게 재시도되면 더 최신인 날씨를 오래된 값으로 덮어쓸 수 있었다.

  * 개선 Action: 주기적 파이프라인에서는 중복 처리뿐 아니라 **실행 순서가 뒤바뀌는 경우까지 고려해 멱등성과 최신성 규칙을 설계**한다.

## 4. Try

* 데이터 수집 파이프라인을 설계할 때 정상 실행뿐 아니라 **재시도·부분 실패·지연 실행 상황을 먼저 시나리오로 만들어 본다.**
