## 1. 오늘 활동

Docker로 Spark Standalone 클러스터를 직접 구성하고 Spark Job을 실행하며 Driver·Worker·Executor의 동작 구조를 확인했다. 이후 NYC 택시 약 1,100만 건의 데이터를 Spark로 정제·집계하고, 시간대별 운행량과 날씨 데이터를 결합해 분석했다.

## 2. Keep

* **개념을 실제 실행 환경과 연결해서 이해한 것.** Master와 Worker를 직접 구성하고 `spark-submit`으로 Job을 실행하면서 Spark의 분산 처리 구조를 확인했다.

  * Action: 분산 처리 기술을 배울 때 **구조를 그림으로만 이해하지 않고 직접 실행해 본다.**
* **큰 데이터를 먼저 정제한 뒤 필요한 단위로 줄여 분석한 것.** 전체 데이터를 그대로 다루기보다 필요한 컬럼과 정상 데이터만 남기고 시간 단위로 집계해 분석했다.

  * Action: 분석 전에 **데이터 크기와 목적에 맞는 전처리·집계 단계를 먼저 설계**한다.

## 3. Problem

* **상관관계만으로 원인을 해석하기 어려웠다.** 날씨와 택시 운행량을 비교했지만 시간대와 같은 다른 요인이 더 크게 작용할 수 있었다.

  * 개선 Action: 결과를 볼 때 **수치뿐 아니라 다른 영향을 주는 변수와 분석의 한계도 함께 확인**한다.

## 4. Try

* 파티션 수나 Worker 자원을 바꾸면서 **병렬 처리 정도가 실행 시간에 어떤 영향을 주는지** 직접 측정해 본다.
* 외부 데이터를 결합할 때 시간대 같은 영향을 통제해 **단순 상관관계보다 한 단계 깊은 분석**을 시도해 본다.
