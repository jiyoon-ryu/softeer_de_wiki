## 1. 오늘 활동

* **한 일**: Hadoop MapReduce의 한계에서 Spark가 등장한 배경을 학습하고, Spark의 전체 구조와 실행 방식을 정리했다. Driver, Executor, Worker, Cluster Manager의 역할과 Standalone·YARN·Kubernetes 환경에서 Spark가 어떻게 실행되는지도 학습했다.

## 2. Keep

* **기술이 등장한 이유부터 이해한 것.** Hadoop은 대용량 데이터를 안정적으로 저장·처리하는 데 초점을 두고, Spark는 반복적인 디스크 I/O를 줄여 더 빠르고 다양한 처리를 지원하기 위해 등장했다는 흐름으로 이해했다.

  * Action: 새로운 기술을 배울 때 **기능만 외우기보다 기존 기술의 어떤 문제를 해결하기 위해 등장했는지 먼저 확인**한다.
* **Spark의 구성요소를 실제 역할과 연결해서 본 것.** Driver가 전체 실행 계획을 세우고, Cluster Manager가 자원을 할당하며, Executor가 Task를 실제 수행한다는 구조로 정리했다.

## 3. Problem

* **Spark 관련 용어가 비슷해 처음에는 실행 구조가 헷갈렸다.** Worker와 Executor의 차이, Local과 Standalone의 차이, Client와 Cluster mode의 차이를 구분해서 이해할 필요가 있었다.

  * Action: 용어를 따로 암기하지 않고 **“어디서 실행되는가 / 누가 자원을 관리하는가 / 실제 계산은 누가 하는가”**를 기준으로 구분한다.
* **Spark가 단순히 ‘메모리를 써서 빠르다’고만 이해하기 쉬웠다.**

  * Action: 메모리 처리뿐 아니라 **병렬 처리, 분산 실행, 장애 복구, 다양한 워크로드를 하나의 엔진에서 처리한다는 특징**까지 함께 본다.
