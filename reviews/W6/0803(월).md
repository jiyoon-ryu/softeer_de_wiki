## 1. 오늘 활동

- **한 일:** 팀 프로젝트 Genesis Premium Route의 문제 정의와 데이터 구조를 구체화했다.
- `Comfort Score`뿐 아니라 실제 개선 효과를 보여주는 **10km당 불편 이벤트 수**를 성과 지표로 설정했다.
- NYC 노면·방지턱·포트홀 데이터와 가상 주행 센서 데이터를 결합한 파이프라인 및 대시보드를 설계했다.

## 2. Keep

- **데이터 상품과 성과 지표를 구분했다.**  
  `Comfort Score`는 경로 선택을 위한 입력값이고, 실제 성과는 승객이 경험하는 충격·진동 감소로 정의했다.
  - **Action:** 이후에도 `데이터 → 의사결정 → 개선 결과`를 구분해 작성한다.

- **구현 범위를 좁혔다.**  
  내비게이션 전체를 구현하지 않고, 주어진 후보 경로의 승차감을 평가하는 API에 집중했다.
  - **Action:** 프로젝트 시작 전 구현 범위와 외부 시스템 역할을 구분한다.

## 3. Problem

- 처음에는 `Comfort Score 62점 → 94점`을 개선 결과로 제시해 실제 사용자 가치가 명확하지 않았다.
  - **개선 Action:** `10km당 불편 이벤트 8회 → 2회`처럼 실제 현상 중심으로 표현한다.

- 공개 주행 데이터는 위치가 익명화되어 NYC 도로 데이터와 직접 연결하기 어려웠다.
  - **개선 Action:** 실제 데이터는 분포 참고에 사용하고, 도로 구간과 연결되는 주행 데이터는 Python으로 생성한다.

## 4. Try

- 최종 대시보드의 지표를 먼저 정한 뒤 필요한 데이터를 역으로 설계한다.
- 이동량이 많은 출발지–목적지 하나와 후보 경로 3개만 대상으로 프로토타입을 만든다.
- 노면이 나쁠수록 충격 이벤트가 증가하도록 가상 데이터 생성 규칙을 명확히 정의한다.
