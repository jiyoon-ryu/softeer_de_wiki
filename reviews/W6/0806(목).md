# 2026-08-06 활동 정리

* **한 일:** 개인 프로젝트 **“Road Comfort 네비게이션”** 프로토타입의 전체 흐름을 구현했다.
  * `segment_reference` 구축
  * OD 선정 및 NetworkX 후보 경로 생성
  * 가상 센서 시뮬레이션
  * Kafka 수집 및 Spark 처리
  * Comfort Score 계산
  * PostGIS 저장
  * 후보 경로 비교 및 FastAPI 제공
  * Before/After 성과 비교
  * Airflow 오케스트레이션
* 정적 시각화와 애니메이션 시각화 아티팩트 2개를 제작했다.
* 별도로 AWS와 Terraform의 VPC, IAM, EC2, Lambda, S3, IaC 개념을 학습했다.

## 2. Keep

* **후보 경로 생성과 Comfort Score 판정을 분리한 것.** NetworkX에서는 거리와 시간만 기준으로 후보 경로를 만들고, 센서 데이터를 처리한 뒤 계산된 Comfort Score로 최종 Comfort 경로를 선정했다. 처음부터 노면등급으로 경로를 만들었다면 원하는 결과가 나오도록 설계한 순환논리가 될 수 있었다.
  * **Action:** 다음 프로젝트에서도 판정 기준과 판정 대상 생성 로직에 동일한 신호를 사용하지 않는다.

* **반복 재시도보다 오류의 근거를 추적한 것.** Airflow 인증 오류가 재시도로 해결되지 않자 GitHub 이슈와 코멘트를 확인해 `EXECUTION_API_SERVER_URL` 미반영과 프로세스 간 시크릿 불일치가 원인임을 찾아 수정했다.
  * **Action:** 동일한 실패가 2회 이상 반복되면 재시도를 멈추고 공식 문서, 로그, 이슈를 통해 원인을 조사한다.

* **프로토타입이라도 End-to-End 흐름을 끝까지 연결한 것.** 개별 기술을 따로 실행하는 데서 끝내지 않고 센서 생성부터 API 응답과 성과 비교까지 하나의 흐름으로 완성했다.
  * **Action:** 이후에도 기능 수를 늘리기 전에 최소 단위의 전체 파이프라인이 먼저 동작하도록 구현한다.

## 3. Problem

* **근거 없는 threshold를 먼저 코드에 적용했다.** 고충격 판정 기준을 `1.5m/s²`로 임의 설정한 뒤 결과가 이상하게 나온 후에야 근거가 부족하다는 점을 확인했다.
  * **개선 Action:** threshold나 가중치를 코드에 넣기 전에 문헌, 실제 데이터 분포, 도메인 기준 중 출처를 한 문장으로 설명할 수 있는지 확인한다.

* **프로세스와 실행 환경을 충분히 정리하지 않고 재시작했다.** Airflow를 다시 실행하는 과정에서 기존 포트 점유 프로세스와 워커가 남아 같은 오류가 반복됐고 원인 파악이 늦어졌다.
  * **개선 Action:** 서비스 재시작 전 포트, 실행 중인 프로세스, 컨테이너, 로그 상태를 확인하고 완전히 정리한 뒤 실행한다.

* **한 번에 구현한 범위가 커서 단계별 정상 여부를 구분하기 어려웠다.** 전체 파이프라인을 빠르게 연결했지만, 중간 단계에서 문제가 생기면 어느 구간이 원인인지 확인하는 데 시간이 들었다.
  * **개선 Action:** 각 단계마다 입력·출력 샘플과 완료 조건을 정의하고, 통과한 단계부터 다음 작업으로 넘어간다.

## 4. Try (새 시도)

* **IaC 개념을 실제 프로젝트 환경에 적용한다.** Terraform에서 학습한 선언형 구성과 `Plan → Apply` 흐름을 참고해, 로컬 Docker와 Airflow 환경도 설정 파일만으로 동일하게 재현할 수 있도록 정리한다.

* **재시도 횟수 제한 규칙을 적용한다.** 같은 오류를 두 번 해결하지 못하면 무작정 다시 실행하지 않고 오류 메시지, 공식 문서, GitHub Issue 순서로 조사한다.

* **파라미터 근거표를 작성한다.** Comfort Score의 threshold, 가중치, ETA 제한 등 주요 수치에 대해 `값 / 출처 / 선택 이유 / 추후 교체 계획`을 기록한다.

* **단계별 검증 체크포인트를 만든다.** Kafka 수신 건수, Bronze 저장 건수, Spark 집계 건수, PostGIS 적재 건수, API 응답 결과를 단계별로 비교해 데이터 누락 위치를 빠르게 확인한다.
